NIP-333

Bitcoin Block Headers over Nostr
Latest Headers How It Works Subscribe Specification GitHub

Verify Bitcoin without trusting anyone. Bitcoin block headers are 80-byte cryptographic proofs. NIP-333 defines a single replaceable Nostr event (kind 33333) carrying the latest twelve headers — small enough for any relay, fresh enough for any wallet, and verifiable by anyone: proof-of-work checks itself, so the publisher is a convenience, never an authority.

How It Works

  • Compact: twelve 80-byte headers — 960 bytes of proof covering roughly two hours of blocks.
  • Replaceable: parameterized replaceable events, one stream per network (d: btc, d: tbtc4, …) — relays store only the newest version. Subscribe once, stay synced.
  • Trustless: every header is verified on receipt — proof-of-work against its own target, each header linking to the previous. This page does exactly that, in your browser, before showing you anything.
  • Bootstrap-friendly: events carry u tags pointing at archive and epoch data sources, so a fresh client can sync the full header chain.

Subscribe via Nostr

["REQ", "headers", {
  "kinds": [33333],
  "#d": ["btc"],
  "limit": 1
}]

Networks: btc (mainnet), tbtc3 (testnet3), tbtc4 (testnet4). See the full specification.

Implementations

  • bitcoin.cc — realtime header dashboard and SPV infrastructure
  • btc-archive — full header chain, epoch files
  • btc-current — current epoch snapshot
